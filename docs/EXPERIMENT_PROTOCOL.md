# 实验协议 v1.0（2026-11-09 冻结）

## 1. 研究问题与判定

**主问题 A**：真实账户 6 个月期末净收益是否大于 0？

**主问题 B**：真实账户（费用后）收益是否高于同期 **510300 ETF 买入持有模拟账户（费用后）**？

两项必须分别回答；**赚钱但跑输基准**不能称为战胜市场。单次 6 个月正收益或超额收益不构成模型具备稳定 alpha 的证据。报告还应列出最大回撤、换手率、成交笔数、费用占本金比例，以及每个模型版本对应的决策数量；不进行未经支持的统计显著性宣称。

## 2. 期间、币种与投资范围

- 计划开始：2026-11-10；计划结束：2027-05-10；时区：Asia/Shanghai。
- 如起始日非交易日、无资金或启动条件不满足：状态保持 PRE_LAUNCH；在实际开始交易的首日记录 actual_start_date，终点以该日后六个日历月为目标并明确版本变更（不得暗改原计划）。
- 账户：人民币；一次性入金 ¥1,000。无追加资金、无出金（特殊异常需记录并将结果标记为偏离协议）。
- 允许：符合券商权限的沪深 A 股普通股票、无杠杆的境内场内 ETF、现金。
- 禁止：融资、融券、保证金、借款、杠杆/反向 ETF、期货、期权、加密货币、场外灰色交易；不得以追赶收益为由放宽。
- 交易必须满足适用证券的实际交易单位、T+规则、涨跌幅、停牌、申赎限制与账户权限；无法确认时选择 **HOLD**。

## 3. AI 自主权与安全边界

AI 可以自主决定：标的、持仓权重、进入/退出、是否持现、是否连续数周不交易。用户仅负责客观执行和反馈；如果风险、账户权限、费用或订单条件不符合本协议，用户应不执行并记录阻断原因。

**硬约束（事先冻结）**：

- 任一单一标的按下单前估算市值不得超过总权益的 **70%**；最多 **3** 个风险标的；允许 100% 现金。
- 每一新买单预计所需现金（价格 × 数量 + 全部费用）必须 ≤ 可用余额；不使用未知佣金或“预计以后上涨”的资金。
- 订单必须是明确的 **限价单**：证券代码、方向、整数数量、最高买价/最低卖价、有效交易时段及过期条件，缺一不可。
- 下单建议当日生成，执行原则上不早于其 Git commit；跨交易日价格或重大信息变化需要重新出具决策。未成交不追价；AI 可在下一次正式决策再提出新订单。
- 不进行自动补仓，不为消除亏损设定最低换手；适用成本较高时优先 HOLD。
- 交易上限：**每个自然周最多 2 笔主动新开仓买单**；卖出不设置人为频率上限但仍需满足规则。不得拆单规避上限。
- 不默认将回撤 10% 或其他任意技术指标设为必然卖出信号；AI 应主动评估风险，但所有卖出决策仍需前置记录。
- 单笔订单在费用、单位或交易许可不清楚时判定不可执行，不得以假成交方式补全数据。

## 4. 决策频率与执行

- 常规评估：每周一 A 股收盘后（北京时间约 20:00），节假日顺延下一交易日收盘后；可以得出 BUY、SELL、HOLD。
- 常规执行：决策形成后的**下一交易日上午 09:35–10:30**，使用预先定义的限价及数量；如未成交，按订单有效期自动视为过期并记录。
- 例外：仅重大信息/预先定义的风险事件可加做一次临时评估；同样必须先提交决策、再执行。
- 需要用户主动在对话中触发每周评估，或另行设置提醒/自动化。**本仓库不会让模型在后台自己持续交易**。
- 每次使用的数据需注明截至时间与来源链接；过期、缺失或不可核实的数据要明确写出来，必要时 HOLD。
- 交易指令必须保证下单时具备可执行性；如券商以市场状态、规则或价格限制拒单，则真实结果为拒单，不以理论收益代替。

## 5. 基准对照

**基准 1：510300 ETF 长期持有**（独立模拟资金 ¥1,000）。在实际启动首日以能够在当时执行的市场价格/时间记录一次模拟买单，按与实盘匹配的交易单位、佣金和现金约束成交，剩余现金保留；其后不主动交易。股息、拆分和其他权益要计入。若模拟成交价格使用了历史报价而非可确认盘口，标记报价假设及偏差，不得称作真实成交。

**基准 2：全现金 ¥1,000**。不假设利息，除非真实现金产品有可核实的收益且已在启动前约定。

绩效以相同的估值日期计算。计算差额：AI 净收益率 - ETF 净收益率（百分点）。基准原则上不参与 AI 的换仓和调参。

## 6. 费用、估值与报告

- **实盘总权益** = 可用/冻结现金合计 + 所有持仓按同日收盘价计的市值 + 已确认但尚未体现于现金或持仓的应收权益（避免重复入账）。
- **净收益率** = (期末总权益 - ¥1,000) / ¥1,000；无追加/撤资前提下成立。
- 每笔真实成交录入成交数量、成交均价、佣金、印花税、其他费用；未成交的价格和数量不能写成 fill。
- 优先使用券商对账单的账户总资产与成交单核验；存入仓库的是匿名化的数值和行情来源，不上传账户识别信息。
- 记录每周/期末快照；最大回撤按已记录的连续快照估计，不能冒充盘中最大回撤。
- 同时展示 **持仓市值** 与 **实际可用现金**；未平仓收益属于浮动盈亏，不能写成已实现收益。
- 终点按最后有效收盘价市值评价，不强制卖出；可额外披露“假设全部清仓的费用后价值”，两者不得混淆。
- 如发生券商故障、分红、送转、退市、停牌、公司行动，记录事件及处理依据。

## 7. 模型升级与审计

- 主账户允许模型升级，但**初始本金、持仓、收益曲线不能重置**。
- 每个决策文件注明模型标识、分析时刻、对话/提示词版本、行情数据截止时间及来源；每次升级追加到 `data/model_changes.csv`。
- 模型升级前的成绩不能归到升级后模型；所有历史记录不因性能差而删除。
- 可选增加固定模型/规则的平行模拟账户，但若旧模型无法调用，应明确停止，**不能把换模型的模拟盘伪装成固定模型对照**。
- Git 提交用于事前证据与追溯，禁止历史改写/force-push（这仍不是独立的密码学公证）。
- 历史数据发现错误时，新增有明确来源及理由的更正条目，不静默覆盖。

## 8. 实验失效与风险披露

如发生超预算注资、杠杆、没有事前记录的自由裁量交易、大量缺失成交单，仍继续公开记录，但须标记为 **PROTOCOL_DEVIATION**，不得将其报告为严格遵循协议的成果。券商强制平仓或公司行动亦须披露。

这项测试不是正式的投资研究、不能证明模型因果能力，也不保证盈利。即使只是 1000 元，也必须接受全部损失的可能。
