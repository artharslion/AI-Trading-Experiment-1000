# 每周操作手册（SOP）

## 0. 实盘启动闸门

将 `data/experiment.json` 的状态从 PRE_LAUNCH 改为 RUNNING 前，需确认：

1. 真实可用资金为 ¥1,000，无旧持仓；不上传敏感券商凭证。
2. 用户提供券商实际 A 股与 ETF 最低佣金、收费方式；未知时保持 PRE_LAUNCH。
3. 核实 100 股/100 份等实际交易单位、价格限制与交易权限；不能假定所有标的完全相同。
4. 创建可复核的 510300 模拟基准开仓记录（如首日无可核实报价，则暂不填充）。
5. 记录实际开始日期、初始账户权益、基准价格与来源。**计划开始日期不代表事实上的开仓日期**。

## 1. 常规每周循环

**星期一收盘后**（遇到非交易日顺延）：用户请求 AI 研究；AI 阅读上次决策、`orders.csv`、`equity.csv`，获取可靠的公开市场信息；自行决定 BUY / SELL / HOLD，并提交一个 `records/decisions/YYYY-MM-DD-NNN.md` 文件（照模板填写）。应先提交 Git commit，后下单。

**下一个交易日上午 09:35–10:30**：用户仅对符合协议的有效限价单进行执行。订单过期、部分成交或失败都如实记录。不填造虚假成交。

**每周复盘**：在 `records/reviews/YYYY-Www.md` 追加净值、比较基准、分析决策是否仍有依据；避免以未来信息反向改写原决策。无交易也要留 HOLD 决策和复盘。

**每 3 个月**：正式比较正收益/相对基准/费用/最大回撤/模型版本；6 个月给出最终评价。

## 2. 强制的 AI 决策字段

一次决策至少写明：ID，生成时间，模型版本，使用的数据及行情截止时刻，现有仓位/现金，BUY/SELL/HOLD，标的代码与名称，买卖方向，整数数量，**限价**，预估手续费和总成本（或卖出净额），订单有效期，理由，反对理由，风险，数据源，以及是否可执行。

如果做 HOLD：仍需写资产状况、依据、为什么暂不交易，下一次评估日；订单字段填 N/A。缺关键数据不应猜测行情并交易。

## 3. CSV 录入

- `data/orders.csv`：**每笔订单一行**。待执行订单、拒单、未成交也要记录；未真实成交时 `filled_qty` 和 `fill_price_cny` 留空。时间统一 `YYYY-MM-DD HH:mm:ss+08:00`。
- `data/equity.csv`：估值日一行。填写现金、持仓市值、其他已确认权益、账户总权益和 510300 模拟基准总权益；未经核实字段保持空白并加备注。
- `data/model_changes.csv`：模型切换时追加，新模型不能获得旧版本的收益归属。
- 实盘现金变化按实际费用计算：买入扣 `成交价×数量 + 所有费用`；卖出加 `成交价×数量 - 所有费用`。
- CSV 内容中含逗号时按标准 CSV 双引号转义；不得把口头预计价当成交价。
- 更正：追加带原 order_id / snapshot_id 的纠错记录，写入 `correction_of` 和理由；不要悄悄编辑旧行。

## 4. 数据保护

本仓库公开。不要提交真实账户名、账户号码、身份证、银行卡、持仓截图中可识别信息、API token、证券交易密码。交易回报只需要数值、代码和时间。

## 5. 运行限制

本项目记录决策，不包含自动实盘下单脚本。AI 不能在无人触发时自行登录券商或持续监控行情；如将来引入定时任务，必须单独记录其数据来源、触发失败和取消机制。任何自动执行必须独立经过用户授权与风控审查。
